# DL/T 645 剩余电流保护断路器 远程监控软件

本科电气工程实习项目 —— 为**带自动重合闸功能的剩余电流保护断路器**开发的
基于 **DL/T 645-2007 扩展规约** 的 GUI 远程监控软件。
以远程监控替代强电操作，安全地进行电气教学实习。

## 功能一览

| 功能页签 | 说明 |
| --- | --- |
| 实时监测 | 三相电压/三相电流/剩余电流(最大相+值)、额定剩余电流动作值与极限不驱动时间、运行状态字1/2 实时轮询显示（数值按状态自动着色）；**设备连续无应答时自动清零显示“通讯中断”，恢复应答后自动刷新** |
| 实时监测（内嵌三相动画） | 三相电路示意动画（**L1/L2/L3 三相 + N**），位于**实时电气量卡片正下方**：三相电源(三相正弦波)—三极断路器 QF—剩余电流互感器(三相+N 全部穿过)—三相负载，直观显示**合闸(带电电流流动)/分闸(绿)/保护故障跳闸(原因/红灯闪烁)/遥控·试验分闸(绿)/漏电指示(ΔI)**，并支持**演示自动重合闸**（仅保护故障跳闸后按设定秒数自动下发合闸，遥控分闸不触发） |
| 远程控制 | 远程合闸/分闸、模拟试跳、自检；支持**预约执行**（延时 0-99 分钟/小时）与取消预约 |
| 参数设置 | 控制字 1-5、电流整定（Ir1/t1/Ir2/t2/Ir3）、电压整定（过压/欠压/缺相）、剩余电流预警百分比与持续时间、定时自检 |
| 事件与统计 | 跳闸次数（按 12 类原因）、事件记录读取（保护动作/自检/闸位/告警/高压失复电/保护投退）、累计运行时间、数据清零 |
| 密码管理 | 0-2 级密码修改（4 字节：级别 + 6 位 BCD），默认密码 `000000` |
| 通信日志 | 每一帧收发 HEX 记录（TX=请求 / RX=应答），并标注控制字含义与操作结果 |

> 界面采用现代浅色蓝白主题（`ttk clam` 样式 + 自适应中文字体）。
> 实时电气量采用**大字数值 + 行底浅灰块**（单位同底色），三相动画为**固定高度圆角卡片**
> （标题色带、流动正弦波、标准阻抗符号、电流白点），漏电接地符号位于独立留白区，
> 不会被底部状态条遮挡。
> 断路器状态配色统一为：**合闸 = 红 `#dc2626`**、**分闸 = 绿 `#16a34a`**、
> **保护故障跳闸 = 红 `#dc2626`**（横幅暗红 `#b91c1c`、QF 边框浅红 `#fecaca` 闪烁）、
> **通讯中断 / 状态未知 = 橙 `#ea580c`**（顶部横幅、QF 边框与触头、状态文字、指示灯一致）。
>
> 状态字1 低 5 位原因码中属于**人为动作**的 `0x0D` 远程试验、`0x0E` 按键试验、
> `0x13` 设置更改、`0x1D` 硬遥控、`0x1E` 软遥控，按**正常分闸**显示（绿色，
> 例如「分闸 · 软遥控(远程分闸)」）；其余原因（剩余电流、过载、短路、缺相、
> 欠压、过压、接地、停电、闭锁、互感器故障、合闸/跳闸失败等）才判定为
> **故障跳闸**并红色闪烁。相关判定见 `gui.py` 的 `is_fault_reason()` /
> `SWITCH_ACTION_REASONS`。

## 运行方式

### 环境要求

- Python 3.8+（自带 `tkinter`）
- `pyserial`（串口通信必需）

```bash
pip install -r requirements.txt
```

```bash
python3 main.py        # 或双击 start_gui.bat
```

界面顶部提供两种 **通信模式**，二选一即可：

- **串口模式（真实设备）**：将 USB-RS485 适配器连接电脑，确认端口
  （Windows 一般为 `COM3`、`COM8` 等，Linux 为 `/dev/ttyUSB0`）；
  上位机 A/B 接设备 RS-485 端子（注意共地），设备通信地址设为 `000000000001`；
  选择/填写端口与波特率（默认 9600，8E1），点击 **[连接设备]**。
- **仿真模式（无设备演示）**：无需任何硬件，选择 **[仿真(无设备演示)]**
  后直接点击 **[连接设备]**，即可用内置虚拟断路器完整演示全部功能
  （轮询监测、分/合闸、试跳、参数读写、事件与统计、改密等）。

连接成功后即可进行轮询监测、远程分/合闸、试跳、参数整定、事件读取、改密等全部操作。

## 关键操作说明

### 身份认证

写数据、控制指令、数据清零、修改密码均需携带 **4 字节密码** 与 **4 字节操作者代码**。
- 密码 = 级别字节(0/1/2) + 6 位十进制 BCD；
- 操作者代码 = 8 位十进制 BCD；
- 级别 0 可读、1 普通操作、2 高级操作；高一级可修改自身及低级别密码。

默认密码：级别 0/1/2 均为 `000000`。

### 控制指令 DI（数据标识）

| 功能 | DI | 说明 |
| --- | --- | --- |
| 远程分闸 | `06 01 01 01` | 立即执行 |
| 远程合闸 | `06 01 02 01` | 立即执行 |
| 模拟试跳 | `06 01 03 01` | 模拟剩余电流故障，检验保护动作 |
| 自检 | `06 01 04 01` | 设备自检 |
| 预约执行 | `06 01 0X 02` | 数据域追加 2 字节：延迟量 NN + 单位 U（U=2 分钟 / U=3 小时） |

### 状态字

- **运行状态字 1**：bit6-5 = 闸位（00 分闸 / 01 合闸），bit4-0 = 跳闸/告警原因（见附录 B）；
- **运行状态字 2**：各位为 1 表示对应事件类别有新增记录，读取新增次数后自动清零。

### 字节序约定（真机实测修正）

依据 DL/T 645-2007 与真机（USB-RS485）日志核对，多字节 **BCD 数值量**
（三相电压/电流、剩余电流、额定动作值、累计次数、整定参数等）在线上
**低字节在前**；日期时间类**分量型字段**（`YYMMDDhhmmss`、`hhmmss`、
`DDhhmm`、密码、操作者代码）仍按书写顺序传输。

- 解码数值量用 `P.bcd_decode_lf()`（GUI 中为 `bcd_num()`）；
- 编码数值量用 `P.bcd_encode_lf()`；
- 分量型字段继续使用 `P.bcd_decode()/bcd_encode()`；
- 地址域 `A0..A5` 低字节在前，由 `encode_addr()/decode_addr()` 处理。

## 常见问题

### 为什么软件里剩余电流显示几 mA，而设备 LCD 显示 0 mA？

软件读的是规约寄存器 `0290FF00`（“当前剩余电流最大相及剩余电流值”），
其报文数据形如 `01 05 00`，含义为：相字节 `01`（位标志：1=A相/2=B相/4=C相）
+ 2 字节 BCD 剩余电流值 `05 00`（低字节在前）= **5 mA**。

从真机日志看，即使断路器处于**分闸、三相电流全为 0** 的状态，该寄存器仍返回 5 mA，
而设备 LCD 的“实时剩余电流”显示 0 mA。这说明**两者不是同一个测量量**：
该寄存器可能含有设备固件的测量基线/保留值，或 LCD 对微小数值做了舍入/过滤显示。

因此这**不是软件的字节序解码错误**（无论高低字节序，`01 05 00` 都解不出 0）。
如需进一步确认，可做一次“模拟试跳”：若剩余电流能跳变到动作值附近并触发分闸，
说明通信链路与解析正确；若该寄存器始终比 LCD 大一个固定值，可按设备说明书做零位校正。

## 项目结构

```
duan_LU/
├── main.py                  # 程序入口
├── requirements.txt
├── README.md
└── dl645_breaker/
    ├── __init__.py
    ├── protocol.py          # DL/T 645 帧编解码、校验、DI 构造
    ├── device.py            # 串口传输层 + 高层操作 API
    ├── simulator.py         # 虚拟断路器仿真器（完整协议应答）
    └── gui.py               # tkinter 主界面（后台通信线程）
```

### 架构

- `protocol.py` 负责帧格式：`68 A0..A5 68 C L DATA CS 16`；
- `device.py` 的 `BreakerClient` 提供面向业务的读写/控制 API，
  `SerialTransport` 对接真实串口，`VirtualTransport` 对接内置虚拟断路器；
- `gui.py` 通过 `CommWorker` 后台线程串行执行所有通信操作，结果经队列回传 UI 线程轮询，保证界面不卡顿；
  顶部 **通信模式** 单选按钮在 `SerialTransport`（串口）与 `VirtualTransport`（仿真）之间切换，
  无需硬件即可演示全部功能。

## 教学安全提示

- 远程合闸/分闸/试跳在**串口模式下为真实断路器动作**，操作前确认现场无人员作业；
- 无硬件或不希望操作真实设备时，请使用**仿真模式**，所有动作仅由内置虚拟断路器处理，安全无风险；
- 实习全程连接真实设备时，强电操作仅在指导教师监督下进行；
- 本软件仅用于教学，不替代专业配电自动化系统。
